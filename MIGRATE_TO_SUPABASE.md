# Migration Checklist: Firebase (Firestore) → Supabase (Postgres)

This document outlines the recommended schema, SQL migration scripts, and a step-by-step checklist to migrate the app backend from Firestore to Supabase (Postgres). It assumes you already have a Supabase project.

## High-level checklist

1. Review app code and identify all Firestore usages (reads, writes, realtime listeners).
2. Create the Supabase tables/schema (SQL provided below).
3. Export existing Firestore data to JSON (if you have production data).
4. Transform Firestore JSON to relational rows (script/ETL step).
5. Import data to Supabase using `psql` or Supabase import tools.
6. Update app code to use `@supabase/supabase-js` client (already added at `src/supabase/client.js`).
7. Add environment variables to Vercel: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and `VITE_SUPABASE_SERVICE_KEY` (server side, optional).
8. Add indexes and policies (RLS) appropriate for your app security needs.
9. Test flows: register/login (Clerk or Supabase Auth), add to cart, checkout, order lifecycle, order history.

## Recommended Schema (Postgres)

-- Users table (linked to Clerk via `clerk_id` if using Clerk for auth)

```sql
create table if not exists users (
  id bigint generated by default as identity primary key,
  clerk_id text unique,
  email text unique,
  name text,
  phone text,
  role text default 'user',
  address jsonb,
  metadata jsonb,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
```

-- Carts and cart items (one active cart per user)

```sql
create table if not exists carts (
  id bigint generated by default as identity primary key,
  user_id bigint references users(id) on delete cascade,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table if not exists cart_items (
  id bigint generated by default as identity primary key,
  cart_id bigint references carts(id) on delete cascade,
  product_id text not null,
  title text,
  price numeric(10,2) not null,
  quantity integer not null default 1,
  meta jsonb,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
```

-- Orders and order items

```sql
create table if not exists orders (
  id bigint generated by default as identity primary key,
  user_id bigint references users(id) on delete set null,
  order_ref text unique,
  status text default 'pending',
  total numeric(12,2) not null,
  delivery_fee numeric(10,2) default 0,
  address jsonb,
  metadata jsonb,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table if not exists order_items (
  id bigint generated by default as identity primary key,
  order_id bigint references orders(id) on delete cascade,
  product_id text not null,
  title text,
  price numeric(10,2) not null,
  quantity integer not null default 1,
  meta jsonb,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
```

-- Indexes (improve common queries)

```sql
create index if not exists idx_users_clerk_id on users(clerk_id);
create index if not exists idx_carts_user_id on carts(user_id);
create index if not exists idx_orders_user_id on orders(user_id);
create index if not exists idx_orders_order_ref on orders(order_ref);
```

## Data migration steps (recommended)

1. Export Firestore collections to JSON via `gcloud` or Firestore export tools.
2. Write a small ETL script (Node.js/Python) that:
   - Maps Firestore document fields to relational columns.
   - Creates `users` rows and maps `uid` -> new `users.id`.
   - Creates carts and cart_items rows using the mapped `user_id`.
   - Creates orders and order_items rows; generate `order_ref` if needed.
3. Use `psql` or Supabase SQL editor to run create-table scripts (above).
4. Use `COPY` / `psql` or Supabase import to insert CSV/JSON transformed data. Example using `psql`:

```bash
psql "postgresql://<db_user>:<db_pass>@<host>:5432/postgres" -c "\copy users(email,name,phone,role,address) from 'users.csv' with csv header"
```

Or use `supabase db import` (see Supabase docs) or the SQL editor for smaller datasets.

## App-side migration notes

- Replace Firestore realtime listeners with client-side polling or Supabase Realtime (Postgres replication). `@supabase/supabase-js` supports realtime subscriptions.
- Use `supabase.from('carts').upsert(...)` or `insert` / `update` for cart persistence.
- For protected server-side operations (e.g. payment webhooks), use a Supabase service role key or serverless functions.
- When using Clerk for frontend auth, store `clerk_id` in `users.clerk_id` and use it to query user profile rows.

## Helpful commands

Start a psql connection to your Supabase DB:

```bash
PGPASSWORD=<password> psql "host=<host> port=5432 dbname=postgres user=<user>"
```

Run SQL migration file:

```bash
psql "<conn_string>" -f migrate_supabase_schema.sql
```
